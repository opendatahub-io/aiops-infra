# C16 — Model provenance in the resolution guide

Status: **NOT STARTED**
Jira: [RHAIENG-6190 — improve conforma-analyze skill](https://redhat.atlassian.net/browse/RHAIENG-6190)
Depends on: existing `ai_model` context handling

## Goal

Include the executing model name and version in the resolution guide output,
immediately below the context confirmation section and adjacent to the existing
`Generated by` line. This makes the model provenance visible in the durable
report without requiring readers to inspect `context.yaml`.

## Current behavior

- `init_conforma_run.py` detects or accepts an `ai_model` value and stores it in
  `context.yaml`.
- `generate_resolution_guide.py` reads that value.
- `guide_renderers.render_metadata_header()` currently appends it to the
  `Generated by` line as `(LLM: <value>)` when available.

The implementation must decide whether the existing inline suffix should be
replaced by a separate explicit provenance line or retained alongside it. The
output should avoid implying that the model generated deterministic data when
it only executed the workflow or assisted with selected adjudication steps.

## Proposed behavior

- Render a separate line directly below the context confirmation/table and
  before or adjacent to `Generated by`, for example:
  `*Model: Claude Sonnet 4.5 (`claude-sonnet-4-5`)*`.
- Preserve the exact raw model identifier from `context.yaml` as evidence.
- Keep the display deterministic and escape or safely render unexpected model
  strings.
- If no model is detected, render an explicit value such as `Unknown` or omit
  the model line according to the final output decision; do not invent a model
  name or version.
- Keep the model provenance separate from the workflow generator identity
  (`aiops-infra conforma-analyze skill`).
- Ensure the same metadata appears whether the guide is rendered from the
  confirmation display or from standalone arguments.

## Tests and validation

- Test a model identifier containing both name and version.
- Test model provenance when it is loaded from `context.yaml`.
- Test an explicit command-line model override.
- Test missing model metadata without fabricating a value.
- Test rendering with confirmation-display input and standalone rendering.
- Update exact-output fixtures for the metadata header and end-to-end guide.
- Maintain the repository’s 97% coverage floor for changed testable code.

## Definition of done

- The resolution guide visibly records model name and version below the
  context confirmation area.
- The raw model identifier is preserved and traceable to `context.yaml`.
- Generator identity and model provenance are separate and unambiguous.
- Missing model information is handled deterministically.
- Unit and end-to-end tests pass with the required coverage floor.
