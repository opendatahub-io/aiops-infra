  ---                                                                                                                                                                                                       
  Where AI is genuinely needed (and why)                    
                                                                                                                                                                                                            
  1. Tekton PipelineRun YAML generation — onboard-component-to-konflux-release-data, add-component-to-rhoai-konflux-central, add-component-to-odh-konflux-central, create-pull-pipelines
                                                                                                                                                                                                            
  The YAML must substitute component-specific values (name, repo, branch, platform) while leaving PAC template variables like {{revision}}, {{target_branch}}, {{source_branch}} verbatim and untouched. A  
  naive sed/template approach will accidentally replace or corrupt them. AI understands the distinction contextually. This is the hardest part to script safely.                                            
                                                                                                                                                                                                            
  2. Prefetch-input detection — add-component-to-rhoai-konflux-central, create-pull-pipelines, integrate-component-with-bundle                                                                              
  
  The detect_prefetch_input.sh script probes the repo for package.json, requirements.txt, go.mod, etc. to set the correct prefetch-input value in the pipeline. When it returns ambiguous or empty results  
  (repo not yet created, unusual build system), a judgment call is required. AI can read the repo structure and make a reasonable inference; a script would either fail or silently set a wrong value.
                                                                                                                                                                                                            
  3. Failure diagnosis and adaptive retry — run-odh-konflux-onboarder-workflow                                                                                                                              
  
  When the GitHub Actions workflow fails, the skill fetches the log and decides whether to retry (transient infra failure) or stop and surface the error. This requires reading unstructured log text and   
  classifying the failure — not scriptable without building a rule engine for every known failure mode.
                                                                                                                                                                                                            
  4. Dockerfile digest validation — validate-component-onboarding-jira                                                                                                                                      
  
  Detecting that FROM instructions are missing @sha256: digests is scriptable with regex. What's not easily scriptable is the recovery guidance — understanding which registry the base image comes from and
   suggesting the correct digest lookup command per image type.
                                                                                                                                                                                                            
  5. Interactive Q&A in create-component-onboarding-jira (the upstream entry point, not a child of the orchestrator but worth noting)                                                                       
  
  Collecting onboarding parameters interactively, fetching README to suggest descriptions, asking follow-up questions — this is inherently a conversational AI task.

  ❯ are we able to automate more parts using scripts if we use python rather than bash?                                                                                                                       

⏺ Yes, significantly. The key constraint isn't bash vs Python in terms of logic — it's that Python has libraries that make the hard problems tractable. Let me go through the specific AI-required areas
  from the previous analysis:                                       
                                                            
  ---
  Where Python changes the picture                                                                                                                                                                          
                                  
  1. Tekton PipelineRun YAML generation — the biggest win                                                                                                                                                   
                                                                                                                                                                                                            
  Current AI need: Must substitute component values while leaving {{revision}}, {{target_branch}}, {{source_branch}} verbatim. Sed/bash can't distinguish between "our" placeholders and Tekton PAC         
  variables reliably.                                                                                                                                                                                       
                                                                                                                                                                                                            
  With Python: Solvable with ruamel.yaml + a custom delimiter convention:                                                                                                                                   
  
  # Store templates using ${COMPONENT_NAME} for our substitutions                                                                                                                                           
  # {{revision}} PAC vars are left untouched in the template file                                                                                                                                           
  from ruamel.yaml import YAML                                                                                                                                                                              
  import string                                                                                                                                                                                             
                                                                                                                                                                                                            
  template = string.Template(open("pipelinerun.yaml.tmpl").read())                                                                                                                                          
  rendered = template.substitute(                           
      COMPONENT_NAME=component_name,                                                                                                                                                                        
      REPO_URL=repo_url,                                    
      BRANCH=branch,                                                                                                                                                                                        
  )
  # PAC vars like {{revision}} survive because string.Template only touches ${...}                                                                                                                          
  yaml = YAML(); yaml.preserve_quotes = True                                                                                                                                                                
  doc = yaml.load(rendered)  # validate it's valid YAML                                                                                                                                                     
  yaml.dump(doc, output_file)                                                                                                                                                                               
                                                                                                                                                                                                            
  ruamel.yaml round-trips YAML without corrupting structure, comments, or unrecognised {{...}} strings. This eliminates the AI requirement entirely for YAML generation.                                    
                                                                                                                                                                                                            
  ---                                                                                                                                                                                                       
  2. Prefetch-input detection — mostly solvable             
                                                                                                                                                                                                            
  Current AI need: When detect_prefetch_input.sh returns ambiguous/empty results, judgment is needed.
                                                                                                                                                                                                            
  With Python: A proper detection hierarchy with confidence scoring is straightforward:                                                                                                                     
                                                                                                                                                                                                            
  DETECTORS = [                                                                                                                                                                                             
      ("gomod",  lambda root: (root / "go.mod").exists()),                                                                                                                                                  
      ("pip",    lambda root: any(root.glob("requirements*.txt"))),                                                                                                                                         
      ("npm",    lambda root: (root / "package-lock.json").exists()),                                                                                                                                       
      ("yarn",   lambda root: (root / "yarn.lock").exists()),                                                                                                                                               
  ]                                                         
                                                                                                                                                                                                            
  def detect_prefetch(repo_path):                                                                                                                                                                           
      hits = [name for name, check in DETECTORS if check(repo_path)]                                                                                                                                        
      if len(hits) == 1:                                                                                                                                                                                    
          return hits[0]   # unambiguous — no AI needed                                                                                                                                                     
      if len(hits) == 0:                                                                                                                                                                                    
          return "none"     # no deps — safe default                                                                                                                                                        
      # Multiple hits — still needs a judgment call, but now rare                                                                                                                                           
      return None  # signal: escalate to AI or user                                                                                                                                                         
                                                                                                                                                                                                            
  This reduces the AI escalation rate from "any ambiguity" to "genuinely mixed build systems" — probably <5% of real repos.                                                                                 
                                                                                                                                                                                                            
  ---                                                                                                                                                                                                       
  3. GitHub Actions failure log parsing — partially solvable
                                                                                                                                                                                                            
  Current AI need: Reading unstructured failure logs and classifying them (transient vs fatal).
                                                                                                                                                                                                            
  With Python: GitHub Actions logs are structured JSON via the API. Known failure patterns can be catalogued:                                                                                               
                                                                                                                                                                                                            
  TRANSIENT_PATTERNS = [                                                                                                                                                                                    
      r"rate limit exceeded",                               
      r"connection timed out",                                                                                                                                                                              
      r"temporary failure in name resolution",
      r"context deadline exceeded",                                                                                                                                                                         
  ]                                                                                                                                                                                                         
  FATAL_PATTERNS = [
      r"no such file or directory",                                                                                                                                                                         
      r"permission denied",                                 
      r"image not found",
  ]                                                                                                                                                                                                         
  
  def classify_failure(log_text):                                                                                                                                                                           
      if any(re.search(p, log_text, re.I) for p in TRANSIENT_PATTERNS):
          return "retry"                                                                                                                                                                                    
      if any(re.search(p, log_text, re.I) for p in FATAL_PATTERNS):                                                                                                                                         
          return "fatal"                                                                                                                                                                                    
      return "unknown"  # still needs AI                                                                                                                                                                    
                                                                                                                                                                                                            
  Handles the common cases automatically. Novel failures still escalate to AI, but those are rare.                                                                                                          
  
  ---                                                                                                                                                                                                       
  4. API interactions — already partially done, Python makes it cleaner
                                                                                                                                                                                                            
  Current state: Most API calls use curl + string manipulation. Python's requests (already used in the .py scripts) with proper retry/backoff handles rate limits, 5xx errors, and pagination without shell
  quoting complexity.                                                                                                                                                                                       
                                                            
  # vs 30 lines of bash curl + jq + retry loops                                                                                                                                                             
  import requests                                                                                                                                                                                           
  from tenacity import retry, stop_after_attempt, wait_exponential
                                                                                                                                                                                                            
  @retry(stop=stop_after_attempt(3), wait=wait_exponential(min=1, max=10))                                                                                                                                  
  def get_mr_status(project_id, mr_iid, token):                                                                                                                                                             
      r = requests.get(                                                                                                                                                                                     
          f"https://gitlab.cee.redhat.com/api/v4/projects/{project_id}/merge_requests/{mr_iid}",
          headers={"Authorization": f"Bearer {token}"},                                                                                                                                                     
          timeout=30,                                                                                                                                                                                       
      )                                                                                                                                                                                                     
      r.raise_for_status()                                                                                                                                                                                  
      return r.json()["state"]

The gap is edge cases where the YAML has unusual formatting (anchors, multi-line strings, comments).
                                                                                                                                                                                                            
  With Python + ruamel.yaml: Anchors, aliases, comments, and block scalars all survive a round-trip. This makes the integrate-component-with-odh-operator and integrate-component-with-bundle YAML edits    
  fully reliable.

How can we use claude as orchestrator but stop it from analyzing the logs and retrying various ways to make things success from a skill?        

  3. The skill instruction removes Claude's agency on failures entirely
                                                                                                                                                                                                            
  The SKILL.md step that invokes a script is written to give Claude no decision surface on failure:
                                                                                                                                                                                                            
  ## Step 8c: onboard-component-to-konflux-release-data                                                                                                                                                     
                                                                                                                                                                                                            
  Run:                                                                                                                                                                                                      
  ```bash                                                                                                                                                                                                   
  RESULT=$(bash "$COMMON_SCRIPTS_DIR/run_step.sh" krd \     
    --component "$COMPONENT_NAME" \                                                                                                                                                                         
    --state     "$PIPELINE_STATE")
  echo "$RESULT"                                                                                                                                                                                            
                                                                                                                                                                                                            
  Read the STATUS= token from the output. Take exactly one of these actions                                                                                                                                 
  and no other:                                                                                                                                                                                             
                                                                                                                                                                                                            
  ┌──────────┬────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
  │  STATUS  │                                                       Action                                                       │                                                                         
  ├──────────┼────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
  │ done     │ Continue to Step 8d.                                                                                               │
  ├──────────┼────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
  │ retry    │ Print "Step krd will retry on next run." and stop.                                                                 │                                                                         
  ├──────────┼────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┤                                                                         
  │ escalate │ Post the log path to Jira with update_jira_issue.py --comment "Step krd needs manual review. Log: <LOG>" and stop. │                                                                         
  └──────────┴────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘                                                                         
                                                            
  Do NOT read the log file. Do NOT attempt to diagnose the failure.                                                                                                                                         
  Do NOT try alternative approaches. Do NOT retry the script.
  The script has already classified the failure and updated pipeline_state.json.
